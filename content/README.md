# Пакеты правил

Пакет правил — это данные, по которым «Открывай» строит персональный маршрут открытия точки.
Новый регион или отрасль — это новая папка `content/<pack-id>/`. Код и интерфейс при этом не меняются.

Пакет проходит строгую проверку (`parseRulesPack` в `packages/core/src/rules/validate.ts`).
**Пакет хотя бы с одной ошибкой не загружается целиком**: лучше не показать маршрут, чем показать непроверенный.

Кроме `pack.yaml`, в папке пакета могут лежать данные раздела «Карта» — методика и снимок индекса мест,
см. [«Индекс мест для карты»](#индекс-мест-для-карты).

## Структура пакета

```yaml
manifest:
  id: kazan-coffee            # kebab-case
  version: 1.0.0              # semver; повышайте при каждом изменении содержания
  title: Кофейня / coffee-to-go, Казань
  region:
    code: kazan
    name: Казань
    aliases: [Kazan]          # другие написания, которые пользователь может ввести текстом
    bbox: { south: 55.6, west: 48.8, north: 55.95, east: 49.4 }  # город по геолокации
  industry: coffee
  checked_at: 2026-09-18      # когда весь пакет последний раз сверяли с источниками
  cities: [kazan]             # значения Profile.city, которые покрывает пакет
  disclaimer: …               # необязательно: текст для пользователя

places:                       # необязательно: места в городе, куда ведут шаги маршрута
  - id: ifns-18-kazan         # kebab-case, уникален среди мест
    name: Межрайонная ИФНС России № 18 по Республике Татарстан
    short_name: ИФНС № 18     # необязательно: подпись метки на карте, до 40 знаков; без неё — name
    address: Казань, ул. Владимира Кулагина, 1
    lat: 55.742130            # широта и долгота; внутри manifest.region.bbox, если он задан
    lon: 49.142156
    osm: way/92939129         # необязательно: объект OpenStreetMap, с которого взяты координаты (node/…, way/…, relation/…)
    note: …                   # необязательно: текст для пользователя о месте
    source:                   # обязательно, все три поля
      url: https://www.nalog.gov.ru/rn16/ifns/16_mri18/
      title: ФНС России — Межрайонная ИФНС № 18 по Республике Татарстан
      checked_at: 2026-09-23  # когда адрес и назначение сверили с официальным сайтом

actions:
  - id: register-business     # kebab-case, уникален в пакете
    title: Зарегистрировать ИП или ООО
    lane: critical            # critical | ops | support
    applies_if: …             # необязательно; без условия действие применяется ко всем
    depends_on: []            # id действий, которые должны быть выполнены раньше (critical и ops не зависят от support)
    duration_days: 5          # сколько дней обычно занимает
    due_days_before_opening: 20  # закончить не позже чем за N дней до открытия (по умолчанию 0; отрицательное — можно после открытия, только у support)
    why: Зачем это нужно — одним-двумя предложениями
    do_now: Что сделать прямо сейчас
    prepare:                  # что подготовить (список, можно пустой)
      - Паспорт
    done_when: Что считается выполненным
    places: [ifns-18-kazan]   # необязательно: id мест из каталога places, где делается шаг
    source:
      url: https://www.nalog.gov.ru/…
      title: ФНС России — регистрация ИП
      checked_at: 2026-09-18  # когда источник проверили
    kind: official_fact       # official_fact | recommendation | test_data
```

### Полосы (`lane`)

| Значение | Смысл |
|---|---|
| `critical` | без этого открыться нельзя или открытие рискованно — кандидаты в «три блокера» |
| `ops` | команда и операционная готовность |
| `support` | можно улучшить или получить поддержку |

`critical` и `ops` делаются до открытия: если какой-то из этих шагов не успеть к выбранной дате, маршрут считает
сроки от самой ранней достижимой. `support` необязателен и дату открытия не сдвигает, поэтому от него не могут
зависеть `critical` и `ops`, и только он может заканчиваться после открытия (отрицательный `due_days_before_opening`) —
пакет, где это не так, не пройдёт проверку.

### Происхождение (`kind`)

| Значение | Когда ставить | Что видит пользователь |
|---|---|---|
| `official_fact` | требование подтверждено официальным источником | «Официальный источник» |
| `recommendation` | практическая рекомендация команды, не норма закона | «Рекомендация» |
| `test_data` | содержание ещё не верифицировано или смоделировано | «Тестовые данные» |

Бриф требует явно помечать смоделированные данные — всё, что не проверено вручную, помечайте `test_data`.

## Места (`places`)

Шаг маршрута может вести в конкретное место города: налоговую, Роспотребнадзор, центр «Мой бизнес».
Места собраны в каталог пакета, а карточка ссылается на них по `id`. Одно место может служить нескольким шагам
(лаборатория — и производственному контролю, и медкнижкам): в данных оно описано один раз, на карте у него одна метка.

- **Только официальные источники.** Адрес и назначение места — официальный факт: `source.url` ведёт на сайт
  самой организации или органа власти, где указан этот адрес. Место, которое не удалось подтвердить так, в пакет
  не добавляется.
- **Своя дата проверки.** `source.checked_at` говорит, когда сверяли именно это место; `manifest.checked_at`
  остаётся датой проверки всего пакета.
- **Происхождение координат — в `osm`.** Координаты не официальный факт: в `osm` укажите объект OpenStreetMap,
  с которого они взяты (`node/…`, `way/…` или `relation/…`), — в API из него получается ссылка `osmUrl`.
  `note` пользователь видит как есть, поэтому в нём только текст о месте, без технических ссылок.
- **Короткая подпись на карте — в `short_name`.** Метку места в разделе «Карта» подписывает `short_name`
  (до 40 знаков, в API — `shortName`), а без него — `name`: полное официальное название заняло бы там три-четыре
  строки. В карточке места и в списке мест название остаётся полным.
- В API места приходят в карточке шага (`places`) и в маршруте (`places`): только места применимых шагов,
  каждое один раз, со списком шагов маршрута, которые к нему ведут.

## Условия применимости (`applies_if`)

Условия ссылаются на ответы онбординга (`Profile`, `packages/core/src/profile.ts`):

| Поле | Значения |
|---|---|
| `format` | `to_go` (coffee-to-go), `cafe` (с посадкой) |
| `city` | код города, например `kazan` |
| `legal_status` | `none` (ещё не зарегистрирован), `ip`, `ooo` |
| `premises` | `searching` (ищу помещение), `signed` (договор есть) |
| `employees` | число нанимаемых сотрудников, `0` — работает один |
| `sells_food` | `true` / `false` — продаёт ли готовую еду |

Операторы:

```yaml
applies_if: { field: legal_status, eq: none }          # равно
applies_if: { field: format, in: [cafe, to_go] }       # одно из
applies_if: { field: employees, gt: 0 }                # gt / gte / lt / lte — только для чисел
applies_if:
  all:                                                 # все условия (И)
    - { field: sells_food, eq: true }
    - not: { field: format, eq: to_go }                # отрицание
applies_if:
  any:                                                 # хотя бы одно (ИЛИ)
    - { field: employees, gte: 1 }
    - { field: legal_status, eq: ooo }
```

## Что проверяет валидатор

- Все обязательные поля на месте, типы и форматы верны (id в kebab-case, даты `YYYY-MM-DD`, версия semver, URL http(s)).
- `id` действий уникальны.
- `depends_on` ссылается только на существующие действия и без повторов, нет зависимости от самого себя и **нет циклов**
  (ошибка показывает цепочку: `a → c → b → a`).
- `critical` и `ops` не зависят от `support`; отрицательный `due_days_before_opening` — только у `support`
  (см. [«Полосы»](#полосы-lane)).
- **Каждое `critical`-действие и каждое `official_fact`** имеет `source.url` и `source.checked_at`.
  Это KPI пилота «0 критических карточек без проверяемого основания».
- Условия используют только известные поля и допустимые значения (например, `format: restaurant` — ошибка).
- `id` мест уникальны, у каждого места есть `source.url`, `source.title` и `source.checked_at`, а координаты лежат
  внутри `manifest.region.bbox` (если он задан) — так ловятся, например, перепутанные широта и долгота.
- `places` карточки ссылается только на существующие места и без повторов. Место, на которое не ссылается
  ни одна карточка, — тоже ошибка: мёртвые данные почти всегда означают опечатку.

Каждая ошибка содержит путь, например `actions[register-business].source.url` или `places[cgie-rt]`,
и понятное сообщение.

## Индекс мест для карты

Необязательная часть пакета: индекс мест для выбора района в разделе «Карта». Три файла в папке пакета:

| Файл | Кто пишет | Что внутри |
|---|---|---|
| `location-criteria.yaml` | человек | методика: `grid` — размер квадрата `cell_meters`, `min_buildings` (с какого числа зданий квадрат входит в индекс) и `min_features` (порог маски застройки для сборки); `criteria` — критерии спроса и штрафы с селекторами OSM, радиусами затухания `decay`, `cap`, нормировкой, важностью по умолчанию, шаблонами фактов, якорями названий и `min_features`; пороги конкуренции; `top` — `size` (сколько лучших мест показывать) и `min_spacing_cells` (минимальное расстояние между ними в квадратах); `linked_actions` — шаги, которым помогает карта; `disclaimer` |
| `location-fixtures.yaml` (необязательно) | человек | эталонные точки: чего ждать от снимка в известных местах города — уровни, индекс, слова факта, название |
| `location-index.json` | скрипт `pnpm --filter @otkryvay/api location-index --pack <pack>` | снимок: квадраты с уровнями 0–100 по критериям (у критерия конкуренции вместо уровня — число прямых и прочих конкурентов в радиусе факта) и столбцами фактов; производная база данных OpenStreetMap (ODbL 1.0), руками не правится |

- **Проверка методики** — `parseLocationCriteria` (`packages/core/src/location/parse.ts`): id в kebab-case и без повторов,
  хотя бы один критерий спроса и не больше одного критерия конкуренции; селекторы — только тип объекта (`node`, `way`,
  `rel` или `nwr`) и фильтры тегов в квадратных скобках, например `nwr["amenity"~"^(university|college)$"]`
  или `node["railway"="subway_entrance"]["network"]`, без операторов и произвольного Overpass QL; расстояния до 5 км,
  в шаблонах фактов — только допустимые подстановки, пороги `niche_ratio < saturated_ratio ≤ exclude_ratio`,
  `linked_actions` без повторов.
- **Сборка.** Скрипт берёт все слои из одного датированного среза OSM и проверяет снимок схемой, пакетом правил
  (`linked_actions` — существующие шаги, начало сетки — внутри `region.bbox`) и эталонными точками; снимок с проваленной
  точкой не заменяет снимок пакета. После правки методики снимок пересобирают: в снимке записан sha256 методики
  (`source.configSha256`), и для Казани тест сверяет его с файлом.
- **Загрузка.** API читает снимки при старте. Снимка нет — карта пакета показывает только места шагов; снимок невалиден —
  ошибка в логе, индекс этого пакета выключен, остальное работает. Этим снимок отличается от `pack.yaml`: пакет с ошибкой
  не загружается, и API не стартует.

Пример с решениями калибровки — [kazan-coffee](kazan-coffee/README.md#индекс-мест-для-карты); пересборка
снимка и лицензии — [README, «Данные карты и лицензии»](../README.md#данные-карты-и-лицензии).
